# Resume Distiller：把真实经历写出「核心贡献感」

> 蒸馏阿酥在 coding（LofiSu）公开简历中的高密度叙事方法，但不蒸馏水分。

不需要 Codex，不需要安装，也不需要懂 Prompt Engineering。

把你的原始简历、目标岗位和 [通用 Prompt](prompts/universal-prompt.md) 一起发给 ChatGPT、Claude、Gemini、DeepSeek、Kimi、豆包或其他大模型，就能开始使用。

## 30 秒开始

1. 打开 [prompts/universal-prompt.md](prompts/universal-prompt.md)，复制完整提示词。
2. 粘贴到任意支持长文本或文件的大模型。
3. 上传原始简历，并补一句目标岗位，例如：`目标岗位：后端开发工程师，输出一页中文简历。`
4. 先确认 AI 给出的“事实账本”，再让它生成最终版本。

最简调用方式：

```text
请按下面的 Resume Distiller Prompt 处理我的简历。
目标岗位：AI Agent 工程师。
模式：Rebuild，包装强度：进取。
所有无法从原文确认的信息放入待确认项，不得自行补全。

[粘贴 universal-prompt.md]
[粘贴简历或上传文件]
```

## 它解决什么问题

普通技术简历经常是任务流水账：

```text
负责开发、参与联调、修复问题、配合上线。
```

优秀表达会回答六个问题：

```text
为什么做 -> 你负责哪一段 -> 难点是什么 -> 如何设计 -> 结果如何 -> 怎么证明
```

Resume Distiller 会先建立事实账本，再把可信信息重构为：

`背景与目标 -> 个人边界 -> 技术链路 -> 关键决策 -> 量化结果 -> 证据`

它尤其适合：

- 技术经历真实，但写出来像“打杂”；
- 项目属于团队，不知道怎样突出个人贡献；
- 有复杂实现，却只写了技术栈；
- 有业务结果，却说不清自己与结果的关系；
- 想针对职位描述改简历，又不想硬贴关键词；
- 担心包装过头，在面试中被连续追问。

## 三档包装强度

| 档位 | 适用情况 | 表达策略 |
|---|---|---|
| 保守 | 国企、研究、合规敏感岗位 | 只改清晰度与顺序，不增强归因 |
| 进取 | 大多数互联网与技术岗位 | 强化问题、机制、结果，严格保留个人边界 |
| 极致可自证 | 竞争激烈且有充分证据 | 最大化叙事密度；每个强主张必须通过追问测试 |

“极致可自证”不等于虚构。没有证据时，工具不会把“参与开发”改成“项目 Owner”。

想纯粹整活、写段子或做虚构角色设定，可以使用独立的 `Fiction` 模式。该模式允许夸张和编造，但所有输出都会带有醒目的虚构声明，不能作为真实简历投递。

## 改写示例：报表导出优化

原始经历：

```text
负责订单报表导出功能，解决数据量大时导出超时的问题。
```

常见但无效的包装：

```text
主导亿级数据中台架构升级，打造高性能分布式导出引擎，大幅提升系统稳定性。
```

问题在于：凭空扩大系统规模，隐藏个人边界，“大幅提升”也没有指标。

有证据时的进取表达：

```text
重构订单报表导出链路，将同步查询改为异步分片任务，并引入游标分页、对象存储与失败分片重试；在单次 50 万行的测试集上，将接口超时率由 18% 降至 0，P95 生成耗时由 11 分钟降至 4.5 分钟。
```

如果原始材料没有这些数字，工具应输出：

```text
重构订单报表导出链路，将同步查询改为异步分片任务，并补充游标分页与失败分片重试，解决大数据量导出占用请求线程和失败后全量重跑的问题。

待确认：最大导出行数、优化前后耗时、超时率、是否使用对象存储。
```

这才是“包装”：提高信息密度和主角感，但不发明事实。

## 工作模式

- `Polish`：保留原结构，优化措辞、顺序和密度。
- `Rebuild`：围绕目标岗位重建项目层级。
- `Tailor`：将已有证据映射到职位描述。
- `Audit`：只检查夸大、模糊、缺指标和追问风险。
- `Interviewer`：扮演面试官，攻击简历中最容易被问穿的主张。
- `Fiction`：娱乐整活或虚构写作；允许编造，但必须显著标注“虚构内容，禁止用于真实求职”。

## 娱乐整活模式

```text
使用 Fiction 模式，把“给社团做了一个报名表”包装成宇宙级基础设施项目。
风格要一本正经、技术黑话密集，但全文必须明确标注虚构，仅供娱乐。
```

Fiction 模式允许虚构指标、规模、职级和架构，但标题、正文首尾都必须显示 `⚠ 虚构内容，仅供娱乐/创作练习，禁止用于真实求职`。默认使用虚构公司名；涉及真实公司时必须标注“平行世界设定”。它不会生成伪造链接、证书、推荐信或背调话术，也不会在用户要求移除虚构标记后继续输出可投递版本。


```text

```

本项目受 LofiSu 公开 GitHub 主页、公开简历截图及其在技术社区引发的简历表达讨论启发。“蒸馏”是对公开写作模式的分析与抽象，不代表本人参与、授权、推荐或背书，也不复制其简历正文。

公开搜索中有关其加入美团 Beam、北斗计划及具体职级的信息主要来自二手报道与社区传闻，本项目不将这些说法作为已确认事实，也不以此作为宣传依据。

真实模式的目标是让真实贡献获得更好的表达，并让每一句话都能经得住面试追问。独立的 Fiction 模式只服务于明确标注的娱乐和创作，不得用于真实求职。
