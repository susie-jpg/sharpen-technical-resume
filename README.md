# Resume Distiller: 把「做了几个需求」写成一套系统

> 从阿酥在 coding（LofiSu）公开简历的高密度表达中蒸馏方法，但不蒸馏水分。

一个面向 Codex 的技术简历强化 Skill。它会把零散经历重构成招聘者容易扫描、面试时经得住追问的项目叙事：

`背景与目标 -> 个人边界 -> 技术链路 -> 关键决策 -> 量化结果 -> 公开证据`

## 为什么做这个 Skill

阿酥的公开简历在中文技术圈引发讨论，很大原因是她非常擅长将工作包装成完整系统叙事：

- 把局部需求放入端到端产品或工程链路；
- 用 Owner、0 到 1、架构升级等强归因词建立主角感；
- 用流程、模块和技术机制提高信息密度；
- 将产品指标、开源身份和外部荣誉集中为可信度信号。

这些方法确实能让简历更有吸引力，但如果个人边界、数字和因果关系不准确，也很容易在技术面试中被追问击穿。

这个 Skill 提炼其有效的叙事方法，并加入三道约束：

1. **事实账本**：区分已验证、待确认和不可使用的主张。
2. **归因边界**：区分主导、共同建设、实现、参与和支持。
3. **抗追问校验**：每个核心主张都要能回答“你具体做了什么、为什么这么设计、结果如何证明”。

## 它能做什么

- 润色中文或英文技术简历；
- 重构 AI、Agent、前端、后端和平台工程项目经历；
- 从截图、PDF、DOCX、Markdown 或零散笔记中提取事实；
- 针对职位描述重新排序证据；
- 找出含糊贡献、无对象指标、过度归因和术语堆砌；
- 在缺少数据时输出待确认问题，而不是编造数字。

## 安装

使用 Codex 的 Skill 安装能力，从本仓库安装 `sharpen-technical-resume` 目录。

也可以将该目录放入本地 Codex Skills 目录：

```text
$CODEX_HOME/skills/sharpen-technical-resume/
```

## 使用

```text
使用 $sharpen-technical-resume 重构我的技术简历，目标岗位是 AI Agent 工程师。
先审计事实和贡献边界，再输出一页中文版；所有缺失指标放在待确认项，不要编造。
```

支持四种模式：

- `Polish`：保留结构，优化措辞和排序；
- `Rebuild`：围绕目标岗位重建层级；
- `Tailor`：针对职位描述映射已有证据；
- `Audit`：只检查夸大、模糊、缺指标和追问风险。

## 改写示例

原始表达：

```text
负责 Agent 平台前端开发，完成了几个页面和接口联调。
```

有证据时可以强化为：

```text
负责 Agent 平台编辑链路的前端落地，覆盖页面新增、区块更新与流程绑定等操作；将模型生成的结构化任务映射为增量 UI Patch，并补充并发执行状态与失败回退，降低多模块生成过程中的等待和整页覆盖风险。
```

它不会在没有证据时改成：

```text
项目 Owner，从 0 到 1 主导 Agent 平台整体架构设计。
```

## 方法来源与声明

本项目受 LofiSu 公开 GitHub 主页、公开简历截图及其在技术社区引发的简历表达讨论启发。“蒸馏”指对公开写作模式的分析与抽象，不代表本人参与、授权、推荐或背书，也不复制其简历正文。

截至整理时，公开搜索中有关其加入美团 Beam、北斗计划和具体职级的信息主要来自二手报道与社区传闻，本项目不将这些说法作为已确认事实，也不以此作为宣传依据。

本项目的目标不是教人伪造履历，而是让真实贡献获得更好的表达，并让每一句话都能经得住面试追问。
