# 示例：订单报表导出优化

## 原始材料

```text
负责订单报表导出功能，解决数据量大时导出超时的问题。后端使用 Java，导出文件放到对象存储。测试时最大导出 50 万行，原来经常超过接口超时时间。后来改成异步任务，支持失败重试。测试记录显示超时率从 18% 降到 0，P95 从 11 分钟降到 4.5 分钟。任务拆分和重试是我设计并实现的，对象存储接入由同事完成。
```

## 事实账本摘要

- 已验证：异步任务、分片、失败重试、50 万行测试、超时率 18% -> 0、P95 11 -> 4.5 分钟。
- 个人边界：设计并实现任务拆分与重试。
- 团队边界：对象存储由同事接入。
- 禁止使用：亿级数据、分布式数据中台、项目 Owner。

## 进取版

```text
设计并实现订单报表异步导出链路，将大查询拆分为可重试的分片任务，并与团队完成对象存储交付；在单次 50 万行测试集上，将超时率由 18% 降至 0，P95 生成耗时由 11 分钟降至 4.5 分钟。
```

## 为什么成立

- “设计并实现”只修饰本人负责的任务拆分与重试。
- “与团队完成”避免把对象存储接入归为个人贡献。
- 数字包含对象、单位、规模和前后基线。
- 没有用“高并发、海量、架构升级”等无法验证的词。
